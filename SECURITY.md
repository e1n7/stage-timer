# Security Policy

## Supported Versions

Security fixes are applied to the latest version on the `main` branch and to the latest production release when practical.

| Version | Supported |
|---|---|
| Latest `main` | Yes |
| Latest production release | Yes |
| Older releases | Best effort |

## Reporting a Vulnerability

Please do not disclose security vulnerabilities in a public issue. Report them privately through GitHub's security-advisory reporting flow for this repository, or contact the project maintainer through the private contact method listed in the repository profile.

Include a clear description of the issue, the affected route or feature, reproducible steps, the expected and actual behavior, and any relevant browser or operating-system details. If the issue involves stored data, remove personal or production data from screenshots and exported files before sharing them.

You should receive an acknowledgement as soon as practical. The project will investigate the report, determine its impact, and coordinate a fix or mitigation before public disclosure whenever possible.

## Scope

Reports involving client-side data exposure, unsafe handling of imported room files, cross-tab message trust, dependency vulnerabilities, or deployment configuration are relevant to this policy. General bugs and feature requests should use the standard GitHub issue templates instead.
